## Зачем этот форк

Upstream 0.1.46 запускает Qwen3.6-35B-A3B на отдельном движке (`src/qwen35`). Там нет пака и кэша экспертов, а
KV-кэш хранится в fp32: 44 KiB на токен, 11 GiB при контексте 262K (по `kv_bytes_per_token` в `setup.py`), то есть
около 70% видеопамяти карты 16 GB.

Форк запускает модели этой архитектуры (`qwen35moe`) на основном движке Flash-Next из пака Strata (`--pack`): int8 KV
(11 KiB на токен, около 2.8 GiB при 262K), кэш экспертов в VRAM, MTP-черновики из слоя внутри GGUF. Так на одной карте
16 GB работает контекст 100K–262K. Цель форка: агент для кода (Codex CLI и подобные) с длинным контекстом на домашнем
ПК.

Без `--pack` файл qwen35moe по-прежнему идёт на движок upstream `src/qwen35`. Путь самой Qwen3.8-Flash-Next не
меняется.

| ---: | ---: | ---: |
| 2K | 0.5 с / 4.7 с (9×) | 291 / 71 (4×) |

### Модели Qwen3.6 / Ornith / Cyber-Tiel на основном движке

- **qwen35moe на пути Flash-Next** (порт aflin на 0.1.46). Файл qwen35moe с `--pack` работает с int8 KV, кэшем
  экспертов, MTP-черновиками (`--spec`) и KV-стримингом. Включено в сборках CUDA и HIP (`STRATA_MAIN_QWEN35`); SYCL
  этот путь не принимает. Чем модель отличается от Flash-Next (один residual-поток, плотное внимание, 8 из 256
  экспертов, гейт DeltaNet `silu`): [QWEN36_PACK.md](QWEN36_PACK.md#what-is-different-from-flash-next).
- **Исправления порта.** Ширина строки tail-skip берётся от модели (раньше `memset` залезал в соседнюю строку); две
  проверки upstream, рассчитанные на форму Flash-Next, больше не останавливают движок на qwen35moe; control vector в
  пути декода применяется простым сложением (раньше гейт hyper-connections читал мусор).
- **Семейства setup** `ornith-abl` (Huihui-Ornith-1.5-35B-A3B-abliterated, IQ4_XS / IQ3_S) и `cyber-tiel`
  (Cyber-Tiel-Coder-35B-A3B, UD-IQ4_XS / UD-IQ3_XXS): ревизии закреплены, размер и SHA-256 проверяются, setup строит пак
  и пишет конфиг с замеренными настройками.

### Скорость на длинном контексте

- **Внимание окна проверки** (`STRATA_ATTN_WINDOW=1`, `STRATA_ATTN_WINDOW_PREC=2`). Окно из T токенов читает K/V один
  раз, а не T раз: при 200K генерация 48.6 → 88.9 ток/с (+83%).
- **Короткие окна** (`STRATA_ATTN_WINDOW_SMALL=1`). Окна до 4 токенов идут через потоковое INT8-ядро, которое при 1–2
  токенах читает K/V на ~790 GB/s из ~960: при 200K 127.6 → 160.7 ток/с.
- **Внимание промпта на INT8 тензорных ядрах** (`STRATA_PROMPT_ATTN_DENSE_IMMA=4`). Обе свёртки внимания идут как
  int8 MMA с точными int32 суммами; ошибка против FP64 2.0e-4, в 5 раз меньше, чем у FP16-режима. Три версии ядра, каждая
  против предыдущей: промпт 200K 76.7 → 60.0, 63.3 → 58.8, 57.6 → 53.8 с; ядро на 64K-чанке 118–127 → 85–97, 96.6–97.0 →
  84.3–85.1, 72.9–73.1 → 62.2–62.3 мс. Значения `=2` и `=3` теперь запускают то же ядро, что `=4`.
- **FP16-режимы внимания промпта** (`STRATA_PROMPT_ATTN_FP16ACC=1|2`): для случая, когда `DENSE_IMMA` не задан
  (int8 или FP16 K/V). Ornith IQ4_XS, промпт 64K: 19.07 → 11.96 с. Setup его не пишет.
- **`STRATA_MMQ_KQ=1`** (переключатель upstream). У UD-IQ4_XS слои 34, 38 и 39 хранят down-проекции экспертов в Q6_K,
  и без библиотеки K-quant они шли медленным FP16-путём: промпт 200K 51.8 → 49.4 с, KL на уровне разброса между
  прогонами. Заодно `STRATA_PREFILL_TIMING` перестал завышать время промпта (раньше +6–9%, теперь 1–6%).
- **`STRATA_ARENA_WSLOCK=1`** (Windows). После длинного промпта пул CPU иногда читал экспертов всего на 13–25 GB/s:
  при нехватке RAM Windows выкидывала арену экспертов из рабочего набора, и каждая 4 KB страница давала page fault.
  Арена закрепляется в рабочем наборе (`VirtualLock`), лишней RAM это не берёт: 200K 129.6 → 166.9 ток/с при
  воспроизведённой нехватке; без нехватки время окна то же или меньше.
- **`router_top10` на CUDA.** Побитово совпадает с прежним; вызов 256 x 8 15.5 → 8.9 мкс, генерация Ornith-1.5 в
  коротком чате 235.7 → 246.7 ток/с. Старое ядро: `STRATA_ROUTER_OLD=1`.
- **`STRATA_ATTN_SPLITS=P`.** Split-K внимания декода по фиксированному числу частей: при 262K резерв VRAM под
  внимание 393 → 30 MiB.
- **`STRATA_GDN_CHUNKED=1` на картах с 64–127 SM**: широкий скан в одну волну, те же биты. Замерено на
  Qwen3.8-Flash-Next (промпт 4K–64K на 0.8–0.9% быстрее). У Qwen3.6, Ornith и Cyber-Tiel 32 головы value, а ядро есть
  только для 48 голов Flash-Next, поэтому на них переключатель ничего не меняет.
- **Диагностика декода.** `STRATA_DECODE_TIMING` выводит строку пула CPU (gate/up, quantize, down, GB/s),
  `STRATA_POOL_STATS=1` — время каждого потока, page faults и долю арены в рабочем наборе. Строки `T` одного окна идут
  одной записью: при выводе в файл окно на 2K тратило на них 4.6 мс из 14, теперь 0.7 мс.

### Качество и повторяемость

- **Детерминированный режим** (`--deterministic` или `STRATA_DETERMINISTIC=1`). Жадный ответ повторяется от запуска к
  запуску: размер окна проверки считается по фиксированной форме стоимости, а не по замеренному времени; нет PcieAuto
  и замеренной CPU-доли промпта; автоматический кэш экспертов режется до целых 512 MiB. Cyber-Tiel: 3 из 3 запусков
  дали одни и те же токены на промптах 300 и 2,048 токенов; без режима ответы расходятся после 12–90 токенов. Нужен для
  A/B-тестов и проверок регрессий.
  [DETAILS.md](DETAILS.md#deterministic-mode-the-same-greedy-answer-every-start---deterministic-opt-in).
- **`"ban_scripts": ["han", "hangul", "kana"]`** в конфиге: токены с иероглифами, хангылем и каной получают смещение
  -100 для каждого запроса. Русский ответ больше не получает слово наполовину по-корейски («ма스크» вместо «маска»). На
  словаре Qwen3.6 это 65,716 из 248,320 токенов, ни одного кириллического или латинского.
- **Ограниченная грамматикой генерация** (`"constrained_tools"`, `"constrained_json"`, opt-in). Вызов инструмента
  генерируется по грамматике из списка инструментов запроса (только объявленные имена и параметры, обязательные на
  месте). `true` — мягкий режим (значение, которое модель начала как текст, остаётся текстом), `"strict"` — JSON для
  каждого нестрокового значения. Нужен пакет `llguidance`, setup его не ставит. На Cyber-Tiel выигрыша нет: в 400 ответах `bench/tool-grammar/stress.py` единственной ошибкой аргументов
  была shell-команда строкой вместо массива, а строгий режим в 3 случаях превращал её в выдуманную валидную команду;
  скорость в пределах разброса. Поэтому выключено по умолчанию и в настройках setup.

### Сервер

- **`"reasoning_loop_recovery": "resample"`.** У upstream есть `"recover"`: он меняет в системном промпте фразу
  высокого усилия на фразу низкого. В системном промпте агента (например, Codex) такой фразы нет, и цикл в рассуждении
  шёл до `max_tokens`. `"resample"` продолжает с того же промпта и вывода с поднятыми temperature и presence penalty, а
  промпт повторного прохода кончается токенами, которые движок записал между STOP и DONE: состояние продолжается, а
  не читается заново (до исправления 209,688 токенов перечитывались 72 с).
- **`"reasoning_close_retry": true`** (#2297) закрывает и рассуждение, которое кончилось внутри набросанного
  `<tool_call>`.
- **Маркеры в тексте ответа** (#2266): регрессионные тесты, что ответ кончается только на id токена конца хода, а не
  на тексте `<|im_end|>`, и заметка для агентов в [таблице проблем](DETAILS.md#troubleshooting).
- **Responses API.** Текстовые файлы в `input_file` попадают в промпт как `<file name="...">`; элементы `mcp_call` и
  `local_shell_call` сохраняются; записи hosted-инструментов от другого сервера отбрасываются, а не ломают разговор.
  PDF, картинки и бинарные файлы отклоняются (`unsupported_file_type`).
- **Кэш разговоров** (#2255). Когда все слоты заняты закреплёнными префиксами, место освобождает самый старый
  разговор, чей префикс держит ещё кто-то. Префикс с единственным владельцем не вытесняется.
- **Разговоры на диске** (`--conversation-disk-dir DIR`, `--conversation-disk-mib N`,
  `--conversation-disk-persist on`). Порт upstream #1937 (xrip) плюс потоковая запись и чтение без копии в RAM:
  разговор, который не помещается в RAM-кэш, пишется с GPU прямо в файл на NVMe и читается обратно прямо в KV-кэш.
  Разговор на 122–125K токенов (1.8 GiB) уходит на диск за 0.8 с и возвращается за 1.0 с; запрос при переключении
  2.4–2.6 с вместо 33–34 с. С `persist on` разговоры переживают перезапуск. [DETAILS.md](DETAILS.md#using-it).
- **`"preserve_thinking"`** (из порта): размышления прошлых ходов остаются в промпте для шаблонов Qwen3.6, Ornith и
  KAT-Coder.

### Setup и Windows

- **Настройки для семейств пака** (`PACK_TUNED` в `setup.py`): что именно пишется — в
  [рекомендуемом конфиге](#рекомендуемый-конфиг).
- **#2261.** KV-стриминг остаётся выключенным, если одна карта держит всех экспертов и весь KV-кэш.
- **`--calibrate-switches`** (opt-in). Setup меряет `STRATA_ADAPT_OVERLAP=1` и `STRATA_ADAPT_LAG=2` на этом ПК: по
  3 запуска движка на вариант, вперемешку. Переключатель остаётся, если медиана лучше базы больше чем на разброс
  самой базы (минимум 3%) и жадный текст совпадает с базой. Победитель пишется в `"env"` конфига.
- **`--calibrate-fork`** (opt-in, семейства пака). Setup подбирает настройки форка под этот ПК на длинном контексте
  (64K, `--calibrate-context N`): глубину окна (`--spec` 3/4/5), порог черновиков и долю PCIe за один запуск движка,
  затем переменные `PACK_TUNED` (и выключает ту, что здесь медленнее) и opt-in переключатели (`STRATA_IQ3S_MT1`,
  `STRATA_ADAPT_OVERLAP`, `STRATA_POOL_FUSED` и другие) по 3 запуска на вариант вперемешку с базой, с проверкой текста.
  `--vram-reserve-mib` и кэш разговоров считаются по свободной VRAM и RAM. Время ограничивает `--calibrate-budget`
  (минуты, по умолчанию 60); план и оценка печатаются до начала. На RTX 5080 + i9-14900K (64K, 21 мин) он оставил
  `PACK_TUNED` как есть (ни один opt-in переключатель не превысил разброс 6% между запусками, выключенные
  `STRATA_ATTN_WINDOW_SMALL`, `DENSE_IMMA`, `MMQ_KQ` медленнее) и поставил `--vram-reserve-mib 1536`: это на 857 слотов
  экспертов меньше и на 9–10% медленнее генерация, чем у рабочего конфига с ~200 MiB свободной VRAM.
  [DETAILS.md](DETAILS.md#tuning-these-settings-per-pc---calibrate-fork).
- **Проба sysmem fallback** (`STRATA_SYSMEM_PROBE=1`, opt-in). На NVIDIA под WDDM драйвер может тихо положить часть
  кэша экспертов в системную RAM, и её чтение идёт со скоростью PCIe. Движок читает кэш при старте и предупреждает,
  называя настройку `Prefer No Sysmem Fallback`; с `--sysmem-fallback-shrink` ещё и урезает кэш. По умолчанию выключена;
  вместе с другими правками интеграции это дало на Ornith IQ4_XS промпт 300 токенов за 299 мс против 329 мс (медиана
  из 5).
- **VirtualAlloc, ошибка 1450** (#2295). Если Windows отказывает в large pages для всей арены экспертов, арена
  сшивается из кусков large pages (1 GiB, при отказе вдвое меньше, до 64 MiB) и 4 KB страниц в одном диапазоне адресов.
  Раньше вся арена уходила на 4 KB страницы. Тестовый переключатель: `STRATA_LARGEPAGES_SIMULATE_1450=N`.
- **`STRATA_STAGE_PIN`**: в DETAILS.md названа причина порчи данных и описана проверка на RTX 5080. Переключатель
  остаётся opt-in.
- **Релизы форка**: готовый движок setup, `UPDATE.bat` / `update.sh` и фид обновлений смотрят на Asofwar/Strata-Turbo
  ([Обновление](#обновление)).

### Инструменты и бенчмарки

- **`tools/mtp_extract.py`**: слой MTP (`blk.40.*`) отдельным файлом из локального GGUF или по ссылке HF (читает
  только заголовок и тензоры слоя). Все найденные головы для Cyber-Tiel оказались одной и той же головой Ornith-1.5 в
  разных квантах: принятие черновиков 81.6–82.4%, в пределах разброса. Оставьте голову из файла модели.
- **`bench/eval-ru`**: 35 пунктов (код с тестами, вызовы инструментов OpenAI, русский язык по рубрикам, поиск
  кодового слова в 32K и 128K) через API сервера. Результаты: [EVAL.ru.md](EVAL.ru.md).
- **`bench/agent-ru`**: 20 агентных задач в маленьких репозиториях на Python и JS/TS (починить тест, реализовать по
  описанию, рефакторинг, ошибка по трейсбеку, флаг CLI, правка в нескольких файлах), инструменты в формате OpenAI,
  скрытые тесты. Результаты: [AGENT-EVAL.ru.md](AGENT-EVAL.ru.md).
- **`bench/tool-grammar/stress.py`**: 50 «неудобных» вызовов инструментов (кавычки, переводы строк, кириллица, JSON
  в строке, SQL) для проверки грамматики.

### Что пробовали и убрали

Код удалён, замеры остались в
[DETAILS.md](DETAILS.md#long-contexts-on-the-pack-path-qwen36--ornith--cyber-tiel-this-fork-opt-in):

- `STRATA_DENSE_MMQ` на CUDA: плотные проекции на 1.1 с быстрее при 200K, но столько же добавили паузы между
  запусками ядер, а KL в 1.6 раза выше разброса. Путь HIP не тронут.
- Правки сборки `-DSTRATA_MMQ_TAB=ON` под MSVC и ширины Qwen3.6 для `STRATA_MMQ_DIRECT`: разница в пределах 2% шума
  (сборка снова как в upstream).
- Отдельные ядра `DENSE_IMMA=2` и `=3`: их заменило `=4`, значения 2 и 3 запускают его.
- Режим точности 3 (`STRATA_PROMPT_ATTN_FP16ACC=3`, `STRATA_ATTN_WINDOW_PREC=3`): в 1.03 раза быстрее `=2` при ошибке
  в 4.5 раза больше; теперь `=3` работает как `=2`.
- `STRATA_ATTN_WINDOW_SMALL` больше 1 (окна 5–6 токенов на маленьком ядре): генерация в пределах разброса; любое
  ненулевое значение теперь значит 1.
- `STRATA_ATTN_WINDOW_SPLITS` (фиксированное число частей окна): замера с выигрышем нет.
- `build-strata-tests.bat` и `bench/eval-ru/fix_recoveries.py`: разовые вспомогательные файлы.

## Рекомендуемый конфиг

### Что setup пишет сам

Для семейств `cyber-tiel` и `ornith-abl` setup пишет в конфиг настройки, замеренные на RTX 5080 16 GB + i9-14900K с
Cyber-Tiel-Coder UD-IQ4_XS ([QWEN36_PACK.md](QWEN36_PACK.md#what-setup-writes-for-these-two)):

| Настройка | Что даёт (замер) |
| --- | --- |
| `STRATA_ATTN_WINDOW=1`, `STRATA_ATTN_WINDOW_PREC=2` | внимание окна проверки за один проход по K/V: 200K 48.6 → 88.9 ток/с, 130K 54.3 → 107.5 |
| `STRATA_ATTN_WINDOW_SMALL=1` | окна до 4 токенов на отдельном ядре: 130K 112.6 → 146.4 ток/с, 200K 127.6 → 160.7 |
| `STRATA_PROMPT_ATTN_DENSE_IMMA=4` | внимание промпта на INT8 тензорных ядрах: 200K 57.6 → 53.8 с, 130K 31.7 → 28.3 с против предыдущей версии ядра |
| `STRATA_MMQ_KQ=1` | эксперты Q6_K через MMQ: промпт 200K 51.8 → 49.4 с (−2…−5% в трёх парах), 130K в пределах разброса, KL на уровне разброса |
| `STRATA_ARENA_WSLOCK=1` | Windows: арена экспертов в рабочем наборе; при нехватке RAM генерация 130K 124.7 → 161.2, 200K 129.6 → 166.9 ток/с; лишней RAM не берёт |
| `--kv-grow` | K/V занимает VRAM по мере роста контекста: 7,668 слотов экспертов на старте вместо 5,519–5,796 |
| `"sampling": {"temperature": 0.6, "presence_penalty": 0}` | сэмплинг для запросов, которые его не задают: 0 испорченных слов из 256 ответов против 16 из 672 при T 1.0 / presence 1.5 ([EVAL.ru.md](EVAL.ru.md)) |
| `"reasoning_loop_recovery": "resample"`, `"reasoning_close_retry": true` | выход из зацикленного рассуждения у агентов (Codex); числового замера нет |

`STRATA_PROMPT_ATTN_FP16ACC` setup больше не пишет: при int8 K/V его перекрывает `DENSE_IMMA`, а q4_0 и k8v4 K/V до
этого ядра не доходят. Если он остался в старом конфиге вместе с `STRATA_GDN_CHUNKED`, оба ничего не меняют на этих
моделях, их можно убрать.

`--kv k8v4` (4-битные V) на этом ПК не ставить: K/V меньше, экспертам остаётся на 184–298 слотов больше, но ядра
`STRATA_ATTN_WINDOW` и `DENSE_IMMA` работают только с int8 K/V. Без них промпт 130K–200K в 7–9 раз дольше, генерация
130K 168.8 → 107.9, 200K 180.1 → 75.1 ток/с, KL в 1.5–2.1 раза выше разброса
([замер](../bench/results/2026-10-22-rtx5080-tiel-kv-k8v4/README.md)). `--kv q4_0` до этих ядер тоже не доходит (по
коду, не замерялся).

`--spec` выше 4 не ставить. На повторе реальных запросов агента (12–206K) `--spec 5`, `6` и `8` не быстрее `--spec 4`,
на 130K–200K скорее медленнее: черновики глубже 4 принимаются так же часто (0.74–0.80), но каждый лишний токен окна
стоит 1–2 мс (эксперты, внимание, шаг черновика). `--spec 8 --mtp-max-t 4` (окна подстановки из контекста до 8 токенов)
даёт +2.5% до 20K и ничего на 130K–200K ([замер](../bench/results/2026-10-22-rtx5080-tiel-spec-depth/README.md)).

### Что добавить вручную

Эти настройки зависят от ПК, поэтому setup их не ставит. Справа замеры на ПК владельца.

| Настройка | Зачем | Замер |
| --- | --- | --- |
| `--draft-vocab cyrillic` (при установке) | MTP-черновики из кириллического подмножества токенов (по умолчанию `cjk`), для ответов на русском | отдельного замера скорости нет |
| `STRATA_IQ3S_MT1=1` | IQ3_S-эксперты на CPU через ядро Strata и для одного токена | вместе с `--kv-grow`: 130K 114.3 → 163.7, 200K 116.8 → 140.2 ток/с; один, без `--kv-grow`: 131.5 → 145.0 и 126.6 → 163.2 |
| `STRATA_ADAPT_OVERLAP=1` | копии адаптивного уровня идут во время следующего окна | +10.2%, +15.3%, +13.9% генерации в трёх прогонах при шуме 11–11.8%, в третьем тот же текст. На других ПК бывает медленнее (RTX 5090 Laptop: −21%): проверяйте через `--calibrate-switches` |
| `STRATA_ATTN_SPLITS=256` | меньше резерв VRAM под внимание при 262K | резерв 393 → 30 MiB, генерация в пределах шума, промпт 4K–32K на 6–14% быстрее (по одному запуску) |
| `STRATA_SYSMEM_PROBE=1` | предупреждение, если драйвер положил часть кэша экспертов в RAM | проба читает 12 GiB, ~15 мс, выход не меняет |
| `--pcie-frac 0.00`, `--spec-min-p 0.50`, `--pool-workers 7`, `--adapt-every 1 --adapt-swaps 160 --adapt-decay 0.97` | доля промахов через PCIe, порог черновиков, потоки CPU, адаптивный кэш | подбираются `--calibrate` на своём ПК (оставляет настройку, только если она быстрее больше чем на 3%); `--pcie-frac 0` на Coder при 66K +66% генерации, на Cyber-Tiel отдельно не замерено |
| `--conversation-cache-mib 4096 --conversation-cache-slots 2 --conversation-cache-min-free-mib 1024` | до двух разговоров в RAM, агент не перечитывает промпт | функция upstream; на этом ПК отдельной A/B-пары нет |
| `--conversation-disk-dir <папка на NVMe> --conversation-disk-mib 32768 --conversation-disk-persist on` | вытесненные разговоры на NVMe, переживают перезапуск | возврат к разговору на ~123K токенов 33–34 с → 2.4–2.6 с (Kingston KC3000) |
| `"ban_scripts": ["han", "hangul", "kana"]` | без иероглифов, хангыля и каны в ответах | 65,716 из 248,320 токенов запрещено, кириллица и латиница не тронуты |

Конфиг лежит в папке данных Strata: `strata-<tag>.json`. Так выглядит конфиг рабочего сервера, на котором сделаны

## Установка

Самый простой способ (Windows, без вопросов, со значком на рабочем столе): `Strata-Turbo-Install.cmd` из релиза,
по шагам — [EASY_INSTALL.ru.md](EASY_INSTALL.ru.md).

Способы получить код форка (все берут файлы из [релизов форка](https://github.com/Asofwar/Strata-Turbo/releases)):
zip релиза `Strata-Turbo-<версия>-windows-cuda13.zip` (Windows, NVIDIA RTX 20 и новее), однострочный установщик
(`irm https://github.com/Asofwar/Strata-Turbo/releases/latest/download/install.ps1 | iex` на Windows, `curl -fsSL
https://github.com/Asofwar/Strata-Turbo/releases/latest/download/install.sh | sh` на Linux) или клон
`git clone https://github.com/Asofwar/Strata-Turbo.git`. Подробнее: [README.ru.md](../README.ru.md#установка). Установщики
приложения (`.exe`, `.AppImage`, `.dmg`), Terminal и подписанный фид форк не выпускает.

Из папки репозитория (Windows):

```
START-HERE.bat --setup --family cyber-tiel
START-HERE.bat --setup --family ornith-abl
```

На Linux то же через `./setup.sh --setup --family cyber-tiel`. Для ответов на русском добавьте
`--draft-vocab cyrillic`. Какой из двух выбрать: по замерам [EVAL.ru.md](EVAL.ru.md) и
[AGENT-EVAL.ru.md](AGENT-EVAL.ru.md) они равны по качеству, Cyber-Tiel быстрее (думает короче) и реже зацикливается;
владелец работает с Cyber-Tiel.

**Что значит путь `--pack`.** Setup скачивает один GGUF (с закреплённой ревизией и SHA-256) и строит рядом пак Strata:
`<data>/packs/<tag>/` с токенизатором и списком экспертов. Эксперты движок читает прямо из GGUF при старте, пак
собирается за секунды. Конфиг запускает движок с `--pack <пак> --native <GGUF> --mtp <GGUF>`. Флаг `--pack` и выбирает
основной движок Flash-Next; без него тот же файл ушёл бы на `src/qwen35` upstream (fp32 KV, без кэша экспертов).

**Готовый движок upstream не подходит**: в нём нет `qwen35moe-pack` в `strata --families`. Setup берёт движок из
релиза форка или собирает его из этого репозитория (на Windows нужен CUDA toolkit, setup спросит перед установкой).

## Обновление

Релизы форка: https://github.com/Asofwar/Strata-Turbo/releases. В каждом лежат:

- `Strata-Turbo-<версия>-windows-cuda13.zip` — исходники форка и готовый движок в папке `engine\`
  (CUDA 13.4, видеокарты NVIDIA RTX 20 и новее: sm_75, 86, 89, 120 и PTX для более новых). Распаковать в папку
  без пробелов в пути и запустить `START-HERE.bat`: setup видит готовый движок (`engine\BUILD.json`,
  `"source": "release"`) и не собирает и не скачивает другой.
- `strata-windows-x64.zip` — только папка `engine\`. Setup скачивает её сам, если `engine\` в установке нет или
  он устарел; SHA-256 сверяется с этим релизом через API GitHub.
- `SHA256SUMS.txt` — контрольные суммы файлов релиза.
- `Strata-Turbo-Install.cmd` и `easy-install.ps1` — простой установщик ([EASY_INSTALL.ru.md](EASY_INSTALL.ru.md)):
  `.cmd` скачивает `easy-install.ps1` из того же релиза, сверяет его с `SHA256SUMS.txt` (если он там указан) и
  запускает.

Как обновить установку:

- Установка через `Strata-Turbo-Install.cmd`: запустить его ещё раз. Новая версия ставится рядом, модель не
  скачивается заново.

- Установка из zip: скачать новый zip форка, распаковать в новую папку и запустить `START-HERE.bat`. Модели в
  `Strata-data` используются повторно, заново ничего не качается.
- Клон репозитория: `UPDATE.bat` (на Linux `update.sh`) делает `git pull` из этого форка и обновляет пакеты Python;
  движок остаётся, пока его версия не ниже `MIN_ENGINE` из `setup.py`. Если setup решит, что движок нужен новый,
  он скачает его из релизов форка (`PREBUILT_URL`, `REPO` в `setup.py` указывают на Asofwar/Strata-Turbo).
- `strata update` не нужен: у форка нет подписанного фида обновлений, команда ничего не найдёт и ничего не поменяет.
  Не запускайте её с фидом upstream (`--feed`, `STRATA_UPDATE_FEED`): она поставит движок upstream, в котором нет
  пути `--pack` для Qwen3.6, Ornith и Cyber-Tiel.
- Не распаковывайте поверх установки zip из upstream (Niko1221/Strata): код upstream ждёт свой движок.
- Конфиг, записанный старым setup, можно не переписывать: лишний `STRATA_PROMPT_ATTN_FP16ACC` ничего не меняет, а
  значения `DENSE_IMMA=2|3`, `FP16ACC=3`, `ATTN_WINDOW_PREC=3` и `ATTN_WINDOW_SMALL` больше 1 работают как
  `=4`, `=2`, `=2` и `=1`. Чтобы получить новые настройки (`STRATA_MMQ_KQ`, `STRATA_ARENA_WSLOCK`), запустите setup
  заново или добавьте их вручную.

Картинки: в релизе нет `strata-vision.exe`, поэтому ввод изображений для моделей Flash-Next setup предложит собрать
из исходников. У Ornith abliterated и Cyber-Tiel картинки выключены в любом случае.

## Ограничения и что не проверено

- **Одно железо.** Всё измерено на одном ПК: RTX 5080 (sm_120), i9-14900K, Windows 11. Другие карты и Linux не
  проверялись; HIP-сборка новых ядер не запускалась (на ПК нет ROCm). SYCL путь `--pack` не принимает.
- **Размеры IQ3** (Ornith IQ3_S, Cyber-Tiel UD-IQ3_XXS) не запускались. Их память в таблицах оценена по файлу.
- **`--batch`** (несколько запросов сразу) на пути `--pack` не запускался. Setup его не предлагает: один запрос за раз.
- **Картинки** для `ornith-abl` и `cyber-tiel` выключены. У Ornith-abl нет mmproj; mmproj Cyber-Tiel не проверялся.
- **Длинные агентные сессии** (100K+ токенов, десятки вызовов) проверены только в работе с Codex, без замера:
  наборы [EVAL.ru.md](EVAL.ru.md) и [AGENT-EVAL.ru.md](AGENT-EVAL.ru.md) короткие (в агентных задачах контекст до 36K).
- **Несколько GPU**: разделение слоёв для этих моделей не сделано.
- **Карты меньше 16 GB** и ПК с меньшим объёмом RAM для этих двух семейств не проверялись.
- **Тесты upstream**: часть собственных тестов upstream падает и без изменений форка. Форк их не чинил.
