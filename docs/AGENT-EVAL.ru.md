# Агентная работа с кодом: Cyber-Tiel-Coder, Huihui-Ornith и KAT-Coder на этом ПК

Проверка, какая модель и какие настройки размышления лучше для Codex, когда модель не отвечает один раз, а
работает как агент: читает файлы, правит их, запускает тесты и так до 25 ходов. Измерено 2026-10-21 и 2026-10-22.
Короткие задачи без агента: [EVAL.ru.md](EVAL.ru.md). Что это за форк и его настройки: [FORK.ru.md](FORK.ru.md).

## Коротко

- Cyber-Tiel и Ornith на этом наборе равны: 53 из 60 прогонов (88%) против 55 из 60 (92%). Разница в два
  прогона меньше разброса: 95%-интервалы 78–94% и 82–96% почти совпадают. Tiel при этом быстрее: 60 прогонов
  заняли 20.8 мин против 25.8 мин, и его размышление реже уходит в петлю (3 срабатывания
  `reasoning_loop_recovery` против 7).
- KAT-Coder-V2.5-Dev UD-IQ4_XS заметно хуже: 36 из 60 (60%, интервал 47–71%). Он думает в 7 раз меньше (465
  токенов размышления на прогон против ~3300) и заканчивает, как только проходят видимые тесты, не проверив
  крайние случаи из описания. В TypeScript он не решил ни одного прогона (0 из 9).
- Ни одна модель ни разу не прислала испорченный вызов инструмента (невалидный JSON, неизвестный инструмент) при
  настройках по умолчанию. Контекст за прогон не превышал 36K токенов.
- Размышление выключать нельзя: без него 28 из 40 (70%). Урезанное размышление (`reasoning_effort: low` или
  `reasoning_budget_tokens: 2048`) дало 33 из 40 (82%), а при бюджете 2048 появились три испорченных вызова.
  `reasoning_effort: high`, бюджет 8192 и `preserve_thinking: false` дали 34, 37 и 36 из 40, то есть в пределах
  разброса от настроек по умолчанию.
- Провалы Cyber-Tiel — его собственные неверные решения, а не сервер: все 19 провалов при настройках по умолчанию
  (из 124 прогонов) проходят видимые тесты и падают на описанном в задаче крайнем случае. Испорченных вызовов,
  обрезок и петель среди причин нет. Ни `terse: false` в шаблоне, ни просьба в промпте агента сверить всё описанное
  этого не меняют: 17 и 18 из 24 против 18 из 24 ([разбор](#почему-cyber-tiel-проваливает-задачи)).
- Рекомендация: оставить Cyber-Tiel с конфигом рабочего сервера ([рекомендуемый конфиг](FORK.ru.md#рекомендуемый-конфиг))
  и настройками размышления по умолчанию. Переходить на Ornith ради этого набора смысла нет, KAT-Coder не брать. Готовый конфиг для другой
  модели не готовил: явного победителя нет.

## На чём мерили

- ПК: NVIDIA GeForce RTX 5080 16 ГБ (драйвер 617.42), Intel Core i9-14900K, 47.7 ГБ RAM, Windows 11.
- Сервер: сборка форка, движок 0.1.46.1, порт 8096. 2026-10-21 — коммит `aac0e4f6`, 2026-10-22 — `47ad95a0` (в нём
  только новая настройка конфига `ban_scripts`, код движка тот же).
- Cyber-Tiel (`tiel`) мерили на рабочем сервере владельца, с его конфигом на те дни:
  Cyber-Tiel-Coder-35B-A3B-MTP UD-IQ4_XS, `--spec 4`, MTP из файла модели, `--kv int8`, сэмплинг temperature 0.6
  и presence_penalty 0, `reasoning_loop_recovery: "resample"`. 57 из 60 его прогонов шли 2026-10-21. С
  2026-10-22 в этом конфиге есть ещё `ban_scripts` (запрет иероглифов и каны): с ним прошли 3 прогона
  `py-impl-retry` и все варианты размышления.
- Ornith (`ornith`): Huihui-Ornith-1.5-35B-A3B-abliterated i1-IQ4_XS, пак `ornith-abl-iq4_xs`.
  KAT (`kat`): KAT-Coder-V2.5-Dev-MTP UD-IQ4_XS из `gbuzhf/KAT-Coder-V2.5-Dev-MTP-GGUF` (sha256 `9a863f49…e73d`
  совпал с HF), пак `kat-coder-v25-iq4_xs` (`tools/iq_pack.py --compat-bf16`). Для обеих
  взят тот же конфиг, сменены только `--pack`, `--native`, `--mtp` и токенизатор. Убраны `--conversation-disk-*`,
  чтобы не писать в дисковый кэш владельца, и нет `ban_scripts` (он запрещает только иероглифы и кану).
- Запросы: `/v1/chat/completions` с инструментами в формате OpenAI, вся история каждый ход, как у Codex. Рассуждения
  прошлых ходов отправляются обратно в `reasoning_content`; хранит ли их шаблон, решает `preserve_thinking`. В
  запросе заданы `max_tokens: 16384` (сервер тогда ограничивает размышление 12288 токенами) и `seed` = 1 + номер
  прогона. Из-за спекулятивного декодирования текст всё равно зависит от времени, поэтому по 2–3 прогона на задачу.

## Набор

Файлы в `bench/agent-ru/`. 20 задач, каждая — маленький репозиторий со своими тестами:

| вид | задачи |
|---|---|
| починить падающий тест | `py-fix-slugify`, `py-fix-lru`, `js-fix-deepmerge`, `ts-fix-arrays` (ru) |
| реализовать по описанию | `py-impl-roman` (ru), `py-impl-intervals`, `py-impl-csvline` (ru), `py-impl-retry`, `js-impl-emitter`, `ts-impl-duration` |
| рефакторинг без поломки тестов | `py-refactor-orders`, `py-refactor-registry`, `ts-refactor-pricing` |
| найти ошибку по трейсбеку | `py-trace-report`, `py-trace-billing`, `js-trace-report` |
| добавить флаг CLI | `py-cli-wordcount` (ru), `js-cli-todo` (ru) |
| правка в 2–3 файлах | `py-multi-email`, `js-multi-paging` |

Python — 12 задач (`unittest`), JavaScript — 5, TypeScript — 3 (`node --test`, Node 24 сам запускает `.ts`). 5
задач поставлены по-русски.

Инструменты агента: `list_dir`, `read_file`, `write_file`, `edit_file` (замена точного куска текста), `search`,
`run_tests`, `run_command` (только `python` и `node`, без shell и без `pip`, 60 с), `finish`. Прогон кончается,
когда модель вызывает `finish`, отвечает без вызова инструмента или делает 25 ходов.

Как засчитывается: после прогона видимые тесты возвращаются в исходный вид (пройти, поправив тест, нельзя),
добавляются скрытые тесты с крайними случаями из описания задачи, и прогон проходит, только если проходят оба
набора. `selftest.py` проверяет каждую задачу: исходный репозиторий скрытые тесты не проходит, эталонное решение
проходит.

Ограничения: задачи маленькие (контекст до 36K), а длинные сессии на 100K+ токенов, где зацикливание вероятнее,
здесь не проверялись. Песочница — это отдельная папка и белый список программ, а не настоящая изоляция.

## Настройки размышления (Cyber-Tiel)

Те же 20 задач по 2 прогона, рабочий сервер, меняется только поле запроса. У шаблона Tiel по умолчанию
`reasoning_effort` = medium и `preserve_thinking` = true (размышления прошлых ходов остаются в контексте);
`high` шаблон понимает как xhigh.

| вариант | прошло | 95%-интервал | ходов | испорченных вызовов | loop recovery | время прогона, среднее / медиана | токенов размышления за прогон | контекст, макс. / среднее |
|---|---|---|---|---|---|---|---|---|
| по умолчанию (3 прогона) | 53/60 (88%) | 78–94% | 9.0 | 0 | 3 | 21 / 16 с | 3286 | 29625 / 6952 |
| `reasoning_effort: low` | 33/40 (82%) | 68–91% | 9.1 | 0 | 1 | 17 / 12 с | 2793 | 23729 / 6408 |
| `reasoning_effort: high` | 34/40 (85%) | 71–93% | 8.6 | 0 | 3 | 20 / 12 с | 3301 | 35722 / 7115 |
| `reasoning_budget_tokens: 2048` | 33/40 (82%) | 68–91% | 9.9 | 3 | 0 | 16 / 12 с | 2361 | 21085 / 6322 |
| `reasoning_budget_tokens: 8192` | 37/40 (92%) | 80–97% | 9.0 | 1 | 1 | 19 / 15 с | 3031 | 16838 / 6766 |
| `preserve_thinking: false` | 36/40 (90%) | 77–96% | 8.6 | 1 | 1 | 18 / 11 с | 2787 | 13536 / 6382 |
| размышление выключено (`reasoning_effort: none`) | 28/40 (70%) | 55–82% | 9.6 | 0 | 0 | 7 / 5 с | 0 | 16788 / 4019 |

- Без размышления модель в 3 раза быстрее, но решает заметно меньше, особенно JS и TypeScript (6 из 16).
- Бюджет 2048 — единственный вариант с несколькими испорченными вызовами (2 вызова без нужного аргумента, 1 с
  лишним аргументом): размышление обрывается, и модель пишет вызов наспех.
- `high` не помог: размышление почти той же длины (3301 токен против 3286), задачи те же.
- `preserve_thinking: false` держит контекст вдвое меньше (максимум 13.5K против 29.6K) и не теряет в качестве на
  этом наборе. На длинных сессиях это может сэкономить память и время чтения промпта, но здесь сессии короткие,
  так что выигрыш не доказан.
- Разница между вариантами по умолчанию, high, 8192 и `preserve_thinking: false` (34–37 из 40 против 88%) меньше
  разброса: два прогона на задачу её не разрешают.

## Почему Cyber-Tiel проваливает задачи

Разбор 2026-10-22: все провалы настроек по умолчанию и вариантов размышления, плюс два новых прогона на рабочем
сервере (тот же конфиг): `diag-tiel` (8 задач, где были провалы, по 3 прогона) и `tiel-codexfmt` (все 20 задач по
2 прогона, вывод команд в виде Codex, см. ниже). Причину каждого провала нового прогона проверял повтором: код из
переписки собран заново и прогнан через скрытые тесты, видно, какая проверка падает.

**Итог: сервер не вызвал ни одного провала.** Все 19 провалов при настройках по умолчанию (из 124 прогонов) — это
неверное или неполное решение самой модели: видимые тесты проходят, скрытые падают на поведении, которое описано в
задаче или в комментарии к коду. Модель проверяет решение видимыми тестами и парой своих примеров и на этом
заканчивает.

| причина | по умолчанию (124 прогона) | варианты размышления (240) |
|---|---|---|
| неверное или неполное решение | 19 | 45 |
| кончились ходы (25) | 0 | 1 (`tiel-think-off:py-impl-csvline#1`: файл остался с синтаксической ошибкой) |
| испорченный вызов инструмента | 0 | 0 |
| ответ обрезан по `max_tokens` | 0 | 0 |
| петля размышления | 0 | 0 |
| неверно прочитан вывод инструмента | 0 | 0 |
| среда или runner | 0 | 0 |
| нестабильный тест | 0 | 0 |

Одно из 45 — `tiel-effort-low:py-impl-csvline#1`: 25 ходов, сработал `reasoning_loop_recovery`, но провал тот же,
что у других (неверный разбор кавычек), а не петля.

Что именно модель пропускает (настройки по умолчанию: `tiel` 60 прогонов, `diag-tiel` 24, `tiel-codexfmt` 40):

| задача | что не сделано | провалов |
|---|---|---|
| `ts-refactor-pricing` | после замены `switch` на таблицу `PLANS[code]` код `"toString"` (ключ `Object.prototype`) проходит без ошибки «unknown plan»; проверку на `"gold"` модель делает сама и видит, что она работает | 7 из 8 |
| `js-impl-emitter` | `once()` хранит обёртку, и `off(fn)` её не находит: слушатель остаётся | 3 из 8 |
| `ts-impl-duration` | принимает `"1 h"` (пробел между числом и единицей), хотя часть — это `<число><единица>` | 2 из 8 |
| `py-trace-report` | исправлен симптом в `report.py`, а `sales_by_day` по-прежнему заводит пустой день (в задаче: «найди настоящую причину») | 2 из 8 |
| `py-fix-lru` | `put()` существующего ключа не делает его самым свежим (исправлен только `get()`, который и проверяет видимый тест) | 2 из 8 |
| `js-fix-deepmerge` | `Date` из `source` становится обычным объектом | 2 из 8 |
| `ts-fix-arrays` | нет `RangeError` для неверного размера | 1 из 8 |

Для `tiel` (без переписок) причина взята из текста падения скрытого теста; для `diag-tiel` и `tiel-codexfmt` — из
повтора. У `tiel:ts-refactor-pricing#0,#2` и `tiel:js-impl-emitter#1` текст падения не отличает этот случай от
соседних проверок того же теста, там причина вероятная. Варианты размышления ошибаются в тех же местах; без размышления добавляются падения на `null`, пустой
строке и `limit=0`.

Что проверено на стороне сервера:

- **Вызовы инструментов.** 0 испорченных при настройках по умолчанию в `tiel` и `diag-tiel`. Всего за 364 прогона 7
  вызовов с лишним или недостающим аргументом; оба в `tiel-codexfmt` — `run_tests` с выдуманным `path` (у
  инструмента нет параметров), и модель следующим ходом вызывает его правильно. Ни один провал из-за таких
  вызовов не случился.
- **Обрезка.** Ни одного ответа с `finish_reason: length`. Самое длинное размышление за один ход — 11142 токена
  (`tiel-codexfmt:py-impl-csvline#1`, прогон прошёл) при пределе 12288 (`answer_room` при `max_tokens: 16384`).
- **Петли.** `reasoning_loop_recovery` сработал 3 раза в `tiel`, 6 в `diag-tiel` и 4 в `tiel-codexfmt`; все эти
  прогоны прошли, кроме `diag-tiel:ts-impl-duration#2`, который упал на том же `"1 h"`, что и прогоны без петли.
- **Конец без `finish`.** Tiel в 48 из 60 прогонов заканчивает текстом, а не вызовом `finish`: так велит его шаблон
  («If you have all necessary data, provide your final answer directly to the user without any tool call»). Работа
  к этому моменту сделана, на результат это не влияет.
- **Шаблон Tiel добавляет в промпт два своих текста**, которые сервер раньше не мог выключить:
  1. Блок «будь краток» в системном сообщении (`Answer directly ... Keep the final answer lean ... ask a sharp
     question, don't guess`), если не передан `terse: false`. Сервер передавал шаблону из `chat_template_kwargs`
     только `enable_thinking`, `reasoning_effort` и `preserve_thinking`, так что совет карточки модели
     (`{"terse": false}`) молча терялся. Теперь это можно задать в конфиге: `"chat_template_kwargs": {"terse":
     false}` (по умолчанию выключено, промпт тот же; см. [DETAILS.md](DETAILS.md)). Блок занимает 180 токенов.
     Без него (`tiel-terse-off`, таблица ниже) прошло 17 из 24 против 18 из 24: качество то же, только модель
     почти всегда заканчивает вызовом `finish` (19 из 24 против 4 из 24).
  2. «⚠️ SYSTEM WARNING: ... Your previous approach is incorrect» после ответа инструмента с `Exit code: N` (N > 0) в
     первых 120 символах. В выводе Codex (`Exit code: 1`, `Process exited with code 1`) это любой упавший тест,
     в том числе ожидаемый. Прогон `tiel-codexfmt` отдаёт вывод команд в этом виде: предупреждение вставлено 53
     раза в 28 прогонах из 40, прошло 34 из 40 против 36 из 40 у тех же прогонов `tiel` (0 и 1). Разница в
     пределах разброса, провалы те же, что и без предупреждений: на этом наборе вреда не видно.
- **Среда.** `node --test tests/` с каталогом в Node 24 на Windows не находит тесты; модель тратит ход и запускает
  файл. `run_command` без оболочки не разбирает `python -c` с вложенными кавычками. Провалов это не вызвало.

Проверка того, что могло бы помочь, на тех же 8 трудных задачах по 3 прогона (рабочий конфиг; сервер на время

## Как повторить

```
python bench/agent-ru/selftest.py
python bench/agent-ru/run_agent.py --url http://127.0.0.1:8096 --tag tiel --runs 3
python bench/agent-ru/run_agent.py --tag tiel-budget-8192 --runs 2 --reasoning-budget 8192
python bench/agent-ru/score.py tiel ornith kat --tasks --kinds
python bench/agent-ru/run_agent.py --tag tiel-codexfmt --runs 2 --exit-format codex
```

`--exit-format codex` отдаёт вывод `run_tests` и `run_command` в виде Codex (`Exit code: N`, `Wall time`,
`Output:`), `--system-extra "..."` дописывает фразу в системный промпт агента, `--template-kwargs '{"terse":
false}'` отправляет `chat_template_kwargs` (сервер передаёт шаблону только ключи из своего
`"chat_template_kwargs"`).

Результаты — `bench/agent-ru/results/<tag>.jsonl`, по строке на прогон; переписки — `results/transcripts/`
(не в git). Повторный запуск пропускает уже сделанные прогоны, `--budget-min` ограничивает окно в минутах.
