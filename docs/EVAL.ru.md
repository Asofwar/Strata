# Качество ответов: Cyber-Tiel-Coder и Huihui-Ornith на этом ПК

Небольшая проверка, какая из двух моделей лучше для Codex и для работы на русском. Измерено 2026-10-21.
Агентные задачи (до 25 ходов с инструментами): [AGENT-EVAL.ru.md](AGENT-EVAL.ru.md). Что это за форк и его
настройки: [FORK.ru.md](FORK.ru.md).

## Коротко

- На этом наборе обе модели почти равны. Ornith чуть точнее в коде (47 из 48 против 44 из 48) и в вызовах
  инструментов (28 из 28 против 25 из 28), но думает дольше: медиана 119 токенов размышления против 76.
- Больше, чем выбор модели, дают настройки сэмплинга. С настройками по умолчанию (как у карточки модели:
  temperature 1.0, presence_penalty 1.5) обе модели иногда портят слово, которое только что написали правильно:
  `ятарь-9948` вместо `янтарь-9948`, `weather` вместо `get_weather`, `Кан伯ра` вместо `Канберра`. С temperature 0.6
  и presence_penalty 0 таких сбоев не было ни одного (0 из 256 ответов против 16 из 672 на temperature 1.0), а
  русские ответы прошли 40 из 40 (Tiel) и 39 из 40 (Ornith).
- Рекомендация: оставить Cyber-Tiel для Codex с блоком `"sampling": {"temperature": 0.6, "presence_penalty": 0}` в
  конфиге (setup для `cyber-tiel` и `ornith-abl` теперь пишет его сам). Ornith — запасной вариант, не хуже по качеству; переходить на него ради этого набора
  смысла нет: разница в коде почти вся из одной задачи, а длинные агентные сессии (где Ornith, по опыту владельца,
  чаще зацикливается) здесь не проверялись.
- Квант покрупнее (UD-Q4_K_XL вместо UD-IQ4_XS) того не стоит: 246 против 243 из 256 ответов, это в пределах
  разброса. При этом он на 12–25% медленнее в генерации и на 22–26% в чтении длинного промпта, и на этом ПК ему не
  хватает RAM. Подробности ниже.

## На чём мерили

- ПК: NVIDIA GeForce RTX 5080 16 ГБ (драйвер 617.42), Intel Core i9-14900K, 47.7 ГБ RAM, Windows 11.
- Сервер: сборка форка на коммите `2a2f2241` (движок 0.1.46.1), порт 8096, конфиг рабочего сервера владельца на тот
  день: `--spec 4`, MTP из файла модели, `--mtp-draft-vocab` cyrillic, `--kv int8`, `--kv-grow`, переменные `STRATA_*`
  того дня (среди них `STRATA_ATTN_WINDOW*`, `STRATA_PROMPT_ATTN_FP16ACC`, `STRATA_GDN_CHUNKED`, `STRATA_IQ3S_MT1`;
  нынешний конфиг: [FORK.ru.md](FORK.ru.md#рекомендуемый-конфиг)). Убраны только `--conversation-disk-*`, чтобы
  прогоны не писали в дисковый кэш владельца.
- Модели:
  - Cyber-Tiel-Coder-35B-A3B-MTP UD-IQ4_XS, пак `cyber-tiel-iq4_xs` (в таблицах `tiel`);
  - Huihui-Ornith-1.5-35B-A3B-abliterated i1-IQ4_XS, пак `ornith-abl-iq4_xs`, MTP из того же
    файла (`ornith`). Это «abliterated» модель: у неё сняты отказы.
- Запросы: OpenAI chat API без полей сэмплинга, как у Codex по умолчанию. Сервер тогда берёт сэмплинг карточки
  Qwen3.6 для режима с размышлением: temperature 1.0, top_p 0.95, top_k 20, presence_penalty 1.5. В запросе задан
  только `max_tokens: 16384`; сервер при этом ограничивает размышление 12288 токенами.

## Набор

Файлы в `bench/eval-ru/`. 35 пунктов, по 4 ответа на пункт (needle — по 2), каждая модель — 128 ответов.

- coding (12): 8 задач на Python и 4 на JavaScript, 4 из них сформулированы по-русски. Код из ответа запускается
  с тестами (`python -I`, `node`). Ответ, где модель не закрыла блок кода, засчитывается, если код верный.
- tools (7): OpenAI tool calling: один вызов с нужными аргументами, два вызова сразу, JSON внутри аргумента,
  вопрос без вызова, ответ по результату инструмента. Аргументы должны быть валидным JSON.
- russian (10): объяснение не длиннее 120 слов, ровно 3 пункта списка, перевод en→ru и ru→en, пересказ в 1–2
  предложениях, одно слово, только JSON, задача с «Ответ: N», исправление ошибок, объяснение «для бабушки». Ответ с
  китайскими или японскими символами не проходит.
- needle (6): кодовое слово в тексте из `docs/*.md` длиной 32K и 128K токенов, на глубине 10, 50 и 90%.
- Зацикливание: ответы, где сервер сработал `reasoning_loop_recovery`, и ответы длиннее 8K токенов размышления.

Запуск: `python bench/eval-ru/run_eval.py --url http://127.0.0.1:8096 --tag tiel --samples 4 --needle-samples 2`,
таблицы: `python bench/eval-ru/score.py bench/eval-ru/results/*.jsonl --fails`. Проверка самих проверок без модели:
`python bench/eval-ru/selftest.py`.

## Сбои копирования

Иногда модель пишет слово правильно в размышлении, а в ответе портит его. Простой счётчик (китайские символы в
ответе, имя инструмента, которого нет в запросе, искажённый код в needle):

| Вариант | Ответов | Сбоев |
|---|---|---|
| tiel, по умолчанию | 128 | 2 |
| ornith, по умолчанию | 128 | 2 |
| tiel, presence_penalty 0 | 128 | 2 |
| ornith, presence_penalty 0 | 128 | 1 |
| tiel, MTP без cyrillic-словаря | 80 | 4 |
| tiel, без экспериментальных `STRATA_*` | 80 | 5 |
| tiel, temperature 0.6 | 128 | 0 |
| ornith, temperature 0.6 | 128 | 0 |

Счётчик не видит опечаток в русском тексте; их я искал глазами. На temperature 1.0 у обеих моделей встречались
слова вроде «видеокарзы заканывается», «наю пальто», «Канбетра». На temperature 0.6 таких стало заметно меньше, но
одна осталась: «надевую» (Tiel) в задаче на исправление ошибок.

Что проверено, чтобы найти причину:

- Не словарь черновика MTP: с полным словарём (без `--mtp-draft-vocab`) сбои те же (4 из 80).
- Не экспериментальные флаги: без `STRATA_PROMPT_ATTN_FP16ACC`, `STRATA_ATTN_WINDOW*`, `STRATA_GDN_CHUNKED`,
  `STRATA_IQ3S_MT1` сбои те же (5 из 80). Зато чтение промпта 128K без них медленнее: needle 34.9 с против 20.1 с.
  (`STRATA_GDN_CHUNKED` на этих моделях ничего не меняет: его ядро есть только для 48 голов value у Flash-Next, а у
  Qwen3.6 их 32.)
- Не только presence_penalty: с presence_penalty 0 и temperature 1.0 сбои остались (2 и 1 из 128).
- Промпт движок читает верно: «повтори дословно» без размышления, greedy, на живом сервере — точная копия обеих
  фраз. С размышлением и тоже greedy Tiel пишет «на улицы» вместо «на улице» уже в размышлении и потом в ответе.
  Значит, это ошибка самой модели (4-битный квант, русский текст внутри английского размышления), а temperature 1.0
  делает её чаще.
- Без speculative decoding проверить нельзя: нативный IQ-пак требует `--spec 2` или больше.

## Заметные ошибки

- Tiel `code-pluralize`: не учитывает отрицательные числа (`-3 яблока`) — 2 из 4 по умолчанию, 3 из 4 на
  temperature 0.6. Это почти вся разница с Ornith в коде.
- Tiel `tool-write-json-ru`: 2 из 4 раз сначала вызывает `run_shell` с `mkdir -p config`, хотя `write_file` создаёт
  папки сам. Разумный осторожный шаг, но лишний.
- Обе модели в `ru-grammar` находят ошибки, которых нет («книга → книгу», «на улицы → на улице»).
- Ornith 6 раз из 48 не закрыл блок кода в конце ответа (и по умолчанию, и на temperature 0.6; код при этом
  верный). Tiel так не делал ни разу.

## UD-Q4_K_XL против UD-IQ4_XS (Cyber-Tiel)

Измерено 2026-10-21, сборка форка на коммите `668083c7`, драйвер 617.42, конфиг рабочего сервера на тот день (с
`STRATA_PROMPT_ATTN_DENSE_IMMA=2`, сэмплинг temperature 0.6 / presence_penalty 0), без `--conversation-disk-*`.

Коротко: **UD-Q4_K_XL не стоит переходить.** По качеству разница в пределах разброса, а работает он медленнее и
не помещается в свободную память этого ПК.

Файлы: `Cyber-Tiel-Coder-35B-A3B-MTP-UD-Q4_K_XL.gguf` (22 749 880 640 байт, sha256
`0bbcf3cc9be4c976bad20e641baf629dad9c178d39ebdc9cd72129179943c06a` совпал с Hugging Face, ревизия `fa19d4f3`), пак
`cyber-tiel-q4kxl` (`tools/iq_pack.py --compat-bf16`). Эксперты в UD-Q4_K_XL: gate/up Q4_K (39 слоёв), Q5_K (1), Q3_K (слой MTP); down Q5_K (36), Q6_K
(4), Q3_K. В UD-IQ4_XS gate/up — IQ3_S, down — IQ4_XS. Движок берёт все эти типы со сборкой
`STRATA_Q6K_EXPERTS=ON` и `STRATA_MMQ_KQUANTS=ON`.

- Разница 243 и 246 из 256 меньше разницы между двумя прогонами одного кванта (126 и 120 у Q4_K_XL).
- В коде почти вся разница — та же задача `code-pluralize` (отрицательные числа): провалена в 6 из 8 ответов у IQ4_XS

### Расхождение распределений (teacher-forced, STRATA_LOGPOS)

Три длинных текста из этого репозитория (исходники и `docs/*.md`), по последним 511 позициям после 64K, 130K и 200K
токенов контекста. Вероятности следующего токена записаны движком (`STRATA_LOGPOS`, top-40). IQ4_XS прогнан дважды,
чтобы видеть шум одного и того же кванта от прогона к прогону.

| Контекст | KL IQ4_XS к IQ4_XS (повтор) | KL IQ4_XS к Q4_K_XL | Перплексия IQ4_XS (2 прогона) | Перплексия Q4_K_XL |
|---|---|---|---|---|
| 64K | 0.0062 | 0.023–0.024 | 2.076 / 2.091 | 2.080 |
| 130K | 0.0106 | 0.031–0.032 | 4.303 / 4.345 | 4.284 |
| 200K | 0.0169 | 0.060–0.063 | 8.989 / 9.175 | 8.873 |
| все 1533 позиции | 0.0112 | 0.039 | | |

Распределения двух квантов действительно разные: KL примерно в 3.5 раза больше шума. Но перплексия на реальном тексте у
Q4_K_XL ниже всего на 0–3%, и это того же порядка, что разброс между двумя прогонами IQ4_XS (0.7–2%). Эталона
(BF16 или Q8) здесь нет, поэтому KL не говорит, какой из квантов ближе к исходной модели.

### Скорость (медиана 3 запросов, без прогревочного)

[FORK.ru.md](FORK.ru.md#результаты). Сравнение двух квантов между собой от этого не меняется.

|---|---|---|---|

### Память

| | IQ4_XS | Q4_K_XL |
|---|---|---|
| Эксперты в RAM (закреплённая память) | 14.12 GiB | 18.32 GiB |
| Свободно RAM перед загрузкой (при сегодняшней нагрузке ПК) | 17.6 GiB | 17.6 GiB |
| Слоты экспертов в VRAM | 7141 (9.85 GiB) | 5622 (10.08 GiB) |
| Свободно VRAM после загрузки | 501–581 MiB | 235 MiB |

- Q4_K_XL не хватает 0.69 GiB RAM. Движок предупреждает, что загрузка может уйти в файл подкачки. Сегодня все
  прогоны прошли, но при большей нагрузке (Docker/WSL, другие программы) это риск.
- В VRAM помещается на 21% меньше экспертов, поэтому больше их считается на CPU. После загрузки остаётся 235 MiB
  VRAM, и движок сам советует `--vram-reserve-mib 977`, а это ещё меньше слотов.

### Итог

Оставить UD-IQ4_XS. Q4_K_XL не дал измеримого выигрыша в качестве на этом наборе. Он медленнее (окно генерации
+12–25%, чтение длинного промпта +22–26%, короткого — в 2 раза), а на этом ПК ему не хватает RAM и почти не остаётся
VRAM. Конфиг для Q4_K_XL не делался.

## Чего здесь нет

- Длинных агентных сессий с десятками вызовов инструментов. Именно там владелец видел, что Ornith чаще зацикливается;
  в коротких задачах этого набора зацикливаний почти нет у обеих моделей.
- Разница в 2–4 ответа из 48 укладывается в разброс от прогона к прогону: по 4 ответа на пункт мало, чтобы делить
  модели на лучшую и худшую по коду.
- Прогоны с temperature 0.6 при presence_penalty 1.5 и без MTP-драфта (`--spec` без `--mtp`) не делались. Из других
  квантов проверен только UD-Q4_K_XL (раздел выше); KL против эталона BF16/Q8 не мерили.

## Как включить рекомендованный сэмплинг

Setup для `cyber-tiel` и `ornith-abl` пишет его сам. В конфиг, записанный раньше (`strata-<tag>.json` в папке данных
Strata), добавить на верхний уровень:

```json
"sampling": {"temperature": 0.6, "presence_penalty": 0}
```

Это действует только на запросы, где клиент сам не задал эти поля. После правки перезапустить Strata.
